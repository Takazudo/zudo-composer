One CMS, five workspaces, one chrome.

The five routes were built incrementally and each grew its own header, library, editor and status vocabulary. This set proposes a single shell, a single library pattern and a single editor pattern, then applies them to Composer, Content, Mapping, Sitemapper and Media. Every page is a click-through prototype; use the widget at the bottom-right of each page to compare sidebar vs top navigation and light vs dark.

What reads as unpolished todayfrom screenshots of the current build and a read of every feature UI

1Three different page headers, two different editor chromes

Composer and Sitemapper use a centered icon-tile header; Content, Mapping and Media use a full-width eyebrow header with status prose on the right. In editors, Composer has a toolbar with “Library”, Sitemapper has “← All sitemaps”, Mapping puts “Library / Save” in the page header, and Content has no back or save affordance at all.

One topbar with a breadcrumb (workspace › record) and one editor toolbar (back · name · mode · actions) on every route.

2Five library layouts, one of them visibly broken

Composer: storage card + rows with always-visible Duplicate/Delete. Mapping: a card that truncates to “Ne… News Pro 2 bindi”. Sitemapper: centered cards. Content: a nested tree. Media: gallery/table tabs with no search, filter or sort anywhere.

One library pattern: header → filter/sort toolbar → table with a row overflow menu, bulk bar, and shared empty/recovery states.

3Status is prose, and it lives in different places

“Content library ready.” / “Mapping library ready.” / “Media library refreshed.” sit as plain text in page headers; Composer and Sitemapper show a “Saved” chip in a toolbar; Content autosaves with no Save button while Mapping requires an explicit Save.

One status chip in the topbar (Saved · Unsaved · Saving · Failed), autosave everywhere, and a Save button that is disabled when there is nothing to save.

4Inspectors and forms scroll before they inform

Composer’s inspector opens with two paragraphs of Reuse guidance before the selected node’s props. Content’s schema mode renders nine field-type cards inline per field. Mapping renders each binding as three stacked card regions.

Inspector tabs (Properties / Slots / Reuse), a field table with a type-picker popover, and one row per binding.

5Row actions are loud, terminology drifts

Every list row carries text buttons (Delete, Duplicate, Reload). Buttons mix “New Collection” with “New composition”. Sitemap/Sitemap s, Composition/“Static Composition”, Mapping/“Content Mapping”/“Mapping route family” appear side by side.

Hover-revealed ⋯ menus, sentence case everywhere, one noun per concept (Composition, Mapping, Sitemap, Entry, Asset).

6Home is a landing page, not a place to work from

The route explains the product to a visitor. There are no counts, no recent records, no “needs attention” list, so the first click is always a guess.

A dashboard with per-workspace counts, recent activity, blocked/unassigned items and quick actions.

Shared rules the prototypes followcontinuing the graphite-and-blue direction already in app-tokens.css

One shell

Dark graphite navigation rail (the unused --color-rail-* tokens already in the app) or a refined top strip; a 48px topbar with breadcrumb, status, search and utilities. Editors add one 44px tool row beneath it.

Accent budget

Blue only for: current nav item, selected row/node, focus ring, the single primary action, and “ready” status. Everything else is neutral. Warning and danger stay semantic.

Two density tiers

32px chrome rows (toolbars, tree, table) and 36px picker rows. Spacing pairs from the same ×2 ladder (4/8/16/32 or 6/12/24) so groups read as groups.

Three-pane editors

Navigator · main · inspector, with real resizers and collapse buttons; on narrow screens the three become a segmented switch in the toolbar. Same skeleton for Composer, Content, Mapping and Sitemapper.

Outline trees, the zudo-doc way

Every navigator tree (Composer structure, Content models and entries, Sitemap pages) uses the same outline: no row icons, a » mark on categories, dashed connectors, a right-aligned mono slug column with Show slug / Show count toggles, square caret toggles, inline “Add” rows at the child indent, and an insert-here `+` that appears when you hover the gap between two siblings. Clicking either opens an inline title input in place.

Quiet rows

Rows show identity, kind and status; actions appear on hover or in a ⋯ menu. Destructive actions are last, separated, and end with an ellipsis.

Shape and depth

5px default radius, 3px for nested controls, hairline borders, flat surfaces. Shadows only on popovers and dialogs. Chips are rectangles, never pills.

02Library pattern

  • Header: icon tile, title, one-line purpose, provider switch, primary “New”.
  • Toolbar: filter, kind, sort, table/cards view.
  • Table rows with ID subline, kind chip, usage, and a hover ⋯ menu.
  • Bulk bar, pagination line, and shared empty / no-match / recovery states.
  • Tabs on the page show the same pattern on Mappings and Sitemaps.
Open 02

03Composer editor

  • Shared toolbar: back, inline-editable name, Edit/Preview and viewport as segmented controls, undo/redo, Export, ⋯.
  • Structure as an outline tree: components as groups, slots as quiet groups, value hints in the mono column, inline “Add component” rows, and a keyboard-driven palette.
  • Inspector tabs Properties / Slots / Reuse; props as a compact label–control grid.
Open 03

04Content editor

  • Models as » categories with entries hanging from dashed connectors, an inline “Add entry” row per collection; Entry / Schema as one segmented switch.
  • Real field widgets: slug with auto-from-title, toggle, markdown editor with a compact toolbar.
  • Schema as a field table; type picker is a popover, not nine inline cards.
  • Preview in the inspector with a “Render through” mapping selector.
Open 04

05Mapping editor

  • Source fields always visible on the left with bound/unbound state.
  • One table row per binding: source → transform → target → status.
  • Inline diagnostics on the failing row; unbound targets listed as chips to bind.
  • Preview and diagnostics in the inspector; Save and Test in the toolbar.
Open 05

06Sitemapper editor

  • Page outline with dashed connectors, route slug column, an assignment dot per page, inline “Add page” rows and an insert-between affordance; hover-only actions.
  • Canvas nodes carry their source (composition, mapping family, or unassigned).
  • Inspector: Page / Source / SEO tabs; Page source is an explicit None / Composition / Mapping choice.
Open 06

07Media library

  • Search, type filter, sort, grid/list view.
  • Compact drop strip instead of a hero-sized upload box; upload progress as rows.
  • Persistent detail panel with copyable URL and Markdown reference, usage, alt text.
  • Dev-only provider status as a chip, not header prose.
