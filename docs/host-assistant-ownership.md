# Host document Assistant ownership

The host page's **Ask Assistant** action hands off the exact saved revision, route,
qualified node and optional property. Select a property for a field edit; select
arrangement for a supported local insertion. The server resolves this selection
again from a coherent public workspace capture. Browser labels and capabilities
are not authority. A stale selection must be selected again.

The actual model system context describes parent-owned slots, child-owned fields,
shared Content and separate domain review. `inspect_owner` exposes the selected
source, supported capabilities and affected uses. Only the exact attached Mapping
(or the active route's Mapping) can establish a Content owner. An unused Mapping
cannot authorize an edit. `propose_content` consumes canonical field IDs and values
from the existing model turn; it does not call a second model. Explicit host
`assistant.contentFields` policy is required. Identity bindings, ambiguous sources,
transformed/structured values and unsupported Content kinds explain their refusal.

Local Composition tools support validated field updates and insertion into the
selected parent's advertised slots. Bound values cannot be shadowed in local props.
Composition and Content receive separate review cards and separate human Apply
buttons; mixed requests are not atomic. The model has no Apply or Undo tool.

Choose a candidate route and render it with the trusted host renderer. Apply is
available only after that exact candidate's frame, renderer, pack, route and revision
acknowledgement. Navigation or canonical changes revoke it; Apply checks the actual
frame again. The server independently checks the captured base inside the appropriate
write barrier. A lost Apply response retains its exact request in browser local
storage scoped by workspace and review, allowing receipt-first recovery after a
browser restart. Undo uses the domain's existing guarded receipt behavior.

The fake provider offers deterministic integration exercises:

- Select a textual property and request `replace "old text" with "new text"`.
- Select a local parent and request `insert "component-id" into "slot-id" with {"text":"Example"}`.

Inspect every separate card and affected use, render the candidate, verify canonical
state is unchanged, Apply, verify the real host output, and test guarded Undo. Repeat
for a local field/insertion, shared course pricing, FAQ and Note Content. Fake-provider
success is not authenticated model inference. Real-provider acceptance requires the
owner's supported credentials and preserved model/effort/tier configuration.

Unsupported requests do not gain authority from a previous conversation. Returning
from a restarted browser can recover saved reviews independently of provider access;
starting a new proposal requires a fresh page selection. Deployment and actual owner
store cutover are outside this workflow.

## Human removal in Page authoring

The Inspector's **Remove component** action is available only for a server-qualified
local, nonroot child. Its canonical Composition parent and named slot determine
ownership even when transparent wrappers are collapsed in the display tree. Shared
Mapping/global sources, mapped parent slots and subtrees owning Mapping attachments
show a refusal reason. This panel conservatively refuses removal when the resulting
Composition has incomplete required slots; it does not change the contract's general
render/export completeness rules. Page roots and shared-source placement removal
remain unsupported here.

Save or explicitly discard a field draft before removal. The action uses the existing
exact-snapshot document-edit path, complete-project validation, operation UUID and
durable receipt recovery. A lost response is recovered with **Recover pending save**,
including after reload or a new browser session. Removal is a human action; it does
not expand the Assistant's model operation grammar.
